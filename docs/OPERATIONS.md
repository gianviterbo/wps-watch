# Operations runbook

Deployment-box specifics for West Philippine Sea Watch. The README covers what the app is;
this covers how to keep it alive.

## Layout

| Thing | Path |
|---|---|
| App | `/data/workspace/wps-watch/` |
| Built page | `site/index.html` (regenerated by `build.py`) |
| Fonts | `site/assets/fonts/*.woff2` (4 files, latin subsets) |
| Env file | `/data/.env`, mode `0600`, read at server start |
| Origin log | `/data/logs/wps-watch/server.log` (requests, errors) |
| stdout/stderr | `/data/logs/wps-watch/out.log` |
| Watchdog log | `/data/logs/wps-watch/watchdog.log` |
| Jev decisions | `/data/logs/jev/` (`caller=wps_watch`) |
| Verdict cache | `/data/state/wps_jev_cache.json` (7 days, versioned) |

## Start, stop, restart

There is no systemd on this box. The origin is a plain `python3 server.py` bound to
`127.0.0.1:8931`, and a scheduled watchdog restarts it when `/api/health` fails.

```bash
# health
curl -fsS http://127.0.0.1:8931/api/health

# restart by hand (exact cmdline + cwd match; a substring match kills the shell running the command)
python3 - <<'PY'
import os, signal
for pid in os.listdir('/proc'):
    if not pid.isdigit(): continue
    try:
        cmd = open(f'/proc/{pid}/cmdline','rb').read().decode('utf8','replace').replace('\x00',' ').strip()
        cwd = os.readlink(f'/proc/{pid}/cwd')
    except Exception: continue
    if cmd in ('python3 server.py', '/usr/bin/python3 server.py') and cwd == '/data/workspace/wps-watch':
        os.kill(int(pid), signal.SIGTERM)
PY
sleep 3 && bash /data/workspace/wps-watch/watchdog.sh
```

The watchdog is a `no_agent` scheduled job (id `61db6d12e521`, every 10 minutes) whose
script is `/data/scripts/wps-watch-watchdog.sh`, a thin wrapper around
`/data/workspace/wps-watch/watchdog.sh`. It is silent when healthy. Recovery was proven by
`SIGKILL`ing the origin and watching the script bring it back.

## Publishing

The hostname is a proxied CNAME into an existing Cloudflare Tunnel; the connector runs on
this box, so the route's service value must be `http://127.0.0.1:8931` (loopback of the
connector's host, not the app's public address). Tunnel and zone identifiers live with the
box's tunnel config, deliberately not in this repository.

Order of work when republishing:

1. `python3 build.py`
2. restart the origin (only if `.py`, `config.json` or env changed)
3. verify `curl -sI https://wps.gdgt.link/` for the CSP hash and headers
4. `LD_LIBRARY_PATH=/data/chromium-libs/all python3 qa.py https://wps.gdgt.link/`
5. check a neighbouring tunnel hostname to prove the route edit did not shadow anything

## Key rotation

1. Edit `/data/.env` (`AISSTREAM_KEY`, `GFW_TOKEN`, `OPENROUTER_API_KEY`).
2. Restart the origin — env is read at startup, and the AIS worker is constructed there.
3. Confirm `/api/summary` reports `vessels.configured: true` and
   `events.configured: true`, and that `vessels.feed.connected` is true within ~30 s.

Never put keys in `config.json`, the repository, or the browser.

## Tuning the filter

- Thresholds: `config.json → news.jev.{ph_min,prc_max}`. Lower `ph_min` to admit more
  wire-style incident reports; raise `prc_max` to admit more attributed PRC statements.
- Disable enforcement without disabling scoring: `news.jev.enforce = false`.
- Kill switch: `JEV_DISABLED=1` in the env, then restart. The rail keeps working and
  reports `filter_state: off`.
- Changing question wording invalidates cached verdicts: bump `CACHE_VERSION` in
  `jev_gate.py`. Do not bump it for threshold changes.
- Judge a wording change by re-scoring the **same** item set (keep a batch of stored items
  and compare bands), never by eyeballing a fresh day.

## Failure modes seen in practice

| Symptom | Cause | Fix |
|---|---|---|
| Every request 500s, watchdog loops | exception inside the header builder (once: a local named `csp` shadowing `csp()`) | fix the exception; health must stay on a dependency-free path |
| Page blank after `build.py` | CSP hash changed but server still serves the old one | server re-reads `csp.json` by mtime; confirm with `curl -sI` |
| Rail shows "filter unavailable" | Jev disabled, capped, or OpenRouter erroring | check `/data/logs/jev/`, `spent_today_usd`, `JEV_DISABLED` |
| Vessel layer shows 0 contacts | terrestrial AIS coverage offshore is genuinely sparse | not a fault; wait for contacts, or move to satellite AIS |
| Event layer empty | no plausible gaps in the window (junk entries are filtered) | check `encounters` count in `/api/events` |
| Cloudflare console error about the beacon | analytics injection vs strict CSP | the origin currently allows Cloudflare's analytics origin by name |
